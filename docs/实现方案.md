## 0. 总体架构

参照 AFFiNE 的分层思路，把"编辑器引擎"与"应用外壳"解耦，一套核心跨全平台复用：

```
┌─────────────────────────────────────────────────────────┐
│  平台外壳（Shell）                                          │
│  Web(Vite) · Desktop(Electron) · Mobile(Capacitor) · HarmonyOS(ArkTS) │
├─────────────────────────────────────────────────────────┤
│  应用层（App / UI）  React + 业务模块 + 设计系统 + i18n      │
├─────────────────────────────────────────────────────────┤
│  编辑器引擎（Editor Core）                                  │
│  块树 + CRDT + 扩展系统 + 业务块 + 白板(gfx)                 │
├─────────────────────────────────────────────────────────┤
│  数据层（本地优先）                                          │
│  存储抽象 → IndexedDB(Web) / SQLite(桌面·移动) + 同步引擎    │
├─────────────────────────────────────────────────────────┤
│  云服务（可选自托管）  NestJS + GraphQL + Postgres + Redis  │
└─────────────────────────────────────────────────────────┘
```

**核心原则**
- 一套编辑器引擎 + 一套 React UI，通过"平台适配层"抹平差异（存储、文件、IPC、原生能力）。
- 数据先写本地，再异步同步到云；无网络也完全可用。
- CRDT 作为唯一事实来源（single source of truth），本地与云都是它的持久化副本。

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | TypeScript（前端）/ Rust（原生模块）/ TypeScript（后端 NestJS） | 与参考项目一致，生态成熟 |
| CRDT | **Yjs**（起步）→ 可选换 y-octo(Rust) | Yjs 成熟稳定，先跑通再优化 |
| 富文本 | ProseMirror / Lexical，或自研 inline 引擎 | 块内富文本编辑基座 |
| 白板渲染 | Canvas 2D + 自研图形层（后期加 WebGL/turbo） | 无边际画布性能关键 |
| UI 框架 | React 18 + Vite | 与参考项目一致 |
| 状态管理 | Jotai（atom）+ 自研 livedata（响应式） | 本地优先场景友好 |
| 桌面 | Electron + electron-builder | Mac/Win/Linux 一套代码 |
| 移动 | Capacitor（封装移动 Web UI） | 复用 Web 代码，成本低 |

| 鸿蒙 | 原生 ArkTS/ArkUI（DevEco Studio） | HarmonyOS NEXT 不支持 Android 运行时，须原生开发 |
| 本地存储 | IndexedDB（Web）/ SQLite（桌面·移动） | 本地优先持久化 |
| 后端 | NestJS + GraphQL + Prisma + PostgreSQL + Redis | 与参考项目一致 |
| 实时同步 | WebSocket（Yjs awareness + update 广播） | 协同编辑 |

## 3. 分阶段实现方案

### 阶段一 · MVP（单机 Web，4–6 周）

**目标**：跑通"块树 + CRDT + 基础块 + 本地存储 + 搜索"的最小闭环。

落地顺序：
1. **CRDT 数据模型** — 用 Yjs 定义块树：每个块是一个 `Y.Map`，子块用 `Y.Array` 保存 id 引用，文档是 `Y.Doc`。封装 `store` 提供 `addBlock / updateBlock / deleteBlock / moveBlock` API。
2. **块 schema 与扩展系统** — 定义块注册表：`{ flavour, model, view }`。每种块声明数据 schema + React 渲染组件。扩展系统用依赖注入注册块/命令/服务。
3. **基础文本块** — paragraph、list（含待办）、code（用 Shiki/Prism 高亮）、divider。块内富文本用 ProseMirror 或 Lexical，光标/选区映射到 CRDT。
4. **编辑器交互** — 斜杠菜单（`/` 触发块类型选择）、拖拽手柄（块重排，写回 CRDT 顺序）、块级快捷键（回车拆块、退格合并、Tab 缩进）。
5. **本地存储** — nbstore 抽象 + IndexedDB 实现，持久化 Yjs update，`y-indexeddb` 起步。撤销/重做用 `Y.UndoManager`。
6. **工作区 + 文档管理** — 工作区 = 一组文档的容器（一个 meta Y.Doc 记录文档列表）。侧边栏文档树、新建/删除/重命名。
7. **全文搜索** — 客户端用 Orama/MiniSearch 建索引，监听块变更增量更新。

验收：能在浏览器创建工作区、写文档、用斜杠菜单插入块、拖拽重排、刷新后数据还在、能搜索。

---

### 阶段二 · 白板 + 富媒体（4–6 周）

1. **白板图形引擎（gfx）** — Canvas 2D 渲染 surface 层，坐标系支持无限平移/缩放。图形模型也存进 CRDT（`surface` 块下的元素 Y.Map）。
2. **白板元素** — shape（矩形/圆/箭头）、brush（手绘路径）、connector（连接线，两端可锚定到元素）、text、group（分组）、mindmap（思维导图，树结构 + 自动布局）。
3. **白板交互** — 指针/选择工具、选中框（selected-rect）、缩放工具栏、框选、自动连线。
4. **note 双模式** — note 块既能在页面模式排版，也能作为白板上的卡片，实现"文档白板融合"。
5. **富媒体块** — image（上传到 blob 存储）、attachment、bookmark（抓取 URL 元信息生成卡片）、embed（iframe 嵌网页）、embed-doc（嵌入内部文档）。
6. **行内能力** — link、reference（双向链接，维护反向引用索引）、@mention、行内 latex（KaTeX 渲染）、footnote。
7. **面板** — 文档标题、大纲（outline，从标题块生成）、画框面板。

验收：能在白板画图形/连线/思维导图，文档能双链跳转，能插图片和嵌网页。

---

### 阶段三 · 桌面 + 移动 + 鸿蒙 + SQLite（6–9 周）

1. **平台适配层** — 定义统一接口（存储、文件系统、剪贴板、窗口），Web/Electron/Capacitor 各自实现。UI 层只依赖接口。
2. **Electron 桌面** — 主进程（窗口管理、菜单、自动更新、深链）+ 渲染进程（加载 core）+ helper 进程。IPC 桥接用类型安全的 preload API。
3. **Rust 原生模块（napi-rs）** — SQLite 绑定替代 IndexedDB（桌面性能更好），媒体捕获/录音（为后续音频转写铺路）。
4. **SQLite 存储实现** — nbstore 增加 SQLite impl，存 Yjs update binary。桌面/移动共用。
5. **打包** — electron-builder 出 macOS(dmg)、Windows(exe/nsis)、Linux(AppImage/deb)。签名与公证（Mac notarization、Win code signing）。
6. **Capacitor 移动** — 封装 mobile web UI，iOS(Xcode 工程) + Android。移动端专属：键盘工具栏、触摸手势、原生 SQLite 插件。
7. **移动 UI 适配** — 响应式布局，移动端简化白板交互。
8. **原生鸿蒙 App** — HarmonyOS NEXT 已不兼容 Android 运行时，无法用 Capacitor 复用移动 Web 代码，须原生开发：用 DevEco Studio + ArkTS/ArkUI 重写界面壳，通过 Web 组件（ArkWeb）承载编辑器引擎，或将核心逻辑编译为可复用的 JS/WASM 由 ArkTS 调用。本地存储用鸿蒙关系型数据库（RelationalStore）或 Preferences 保存 Yjs update binary，实现同一套存储抽象接口。

验收：Mac/Win/Linux 有可安装包，iOS/Android/鸿蒙能跑通，本地数据分别存 SQLite / 鸿蒙 RelationalStore，离线可用。

> ⚠️ 安全提示：Electron 主进程务必开启 `contextIsolation`、禁用 `nodeIntegration`，preload 只暴露白名单 API；深链/文件打开需校验来源。

> 📌 鸿蒙说明：鸿蒙是三平台中成本最高的一环——不能复用 Capacitor 外壳。推荐策略：① 优先用 ArkWeb 内嵌编辑器引擎（复用度高、见效快）；② 性能敏感的存储/同步/CRDT 合并用 ArkTS 原生实现并对齐存储抽象接口；③ 若资源有限可作为阶段三的独立子里程碑延后交付，不阻塞 iOS/Android。

---

### 阶段四 · 云 + 协作（6–8 周）

1. **后端骨架** — NestJS + GraphQL + Prisma(Postgres) + Redis。docker-compose 起本地依赖。
2. **认证** — magic-link 无密码登录 + OAuth（Google/GitHub）。session 用 cookie，客户端唤起用 open-app 深链。
3. **工作区（云）** — 工作区 CRUD、成员管理、邀请。文档授权 doc-grants（谁能读/写）。
4. **文档同步** — 实时同步网关（WebSocket）：客户端推送 Yjs update，服务端合并（Rust 原生 merge-updates）并广播给其他在线端。冲突由 CRDT 自动解决。
5. **实时协同 UI** — awareness 广播光标/选区，渲染他人光标（remote-selection）。
6. **blob 存储** — 图片/附件传到 S3/R2 兼容对象存储，本地缓存。
7. **协作附加** — 评论（块级 + 实时）、通知（站内 + 邮件）、分享文档（公开链接 + 权限）。
8. **权限与配额** — 权限模型、存储/成员配额、特性开关。
9. **自托管** — Docker 镜像 + 初始化向导 + 管理后台（admin，用户/实例/配置管理）。

验收：多人能实时协同编辑同一文档、看到彼此光标、评论、分享，且可 Docker 自托管。

> ⚠️ 安全提示：同步网关需鉴权（每条连接校验 session + 文档权限），blob 上传需限流和类型校验，公开分享链接需可撤销。

---

### 阶段五 · AI + 多视图数据库 + 商业化（按需）

1. **多视图数据库块** — database 块 + data-view（表格/看板视图）+ 字段类型（文本/数字/选项/日期/关联/公式）。数据存 CRDT。
2. **AI Copilot** — 后端 copilot 插件：多模型供应商适配（OpenAI/Anthropic/Gemini）+ BYOK。流式输出（SSE/WebSocket）。
3. **AI Agent 工具** — 文档读写编排、分段编辑、联网搜索（Exa）、代码/产物生成。
4. **RAG** — 文档向量嵌入 + indexer 服务（pgvector）+ 语义检索。
5. **音频转写** — 配合桌面录音原生模块，transcript 转文字。
6. **MCP** — 支持 Model Context Protocol 接入外部工具。
7. **商业化** — Stripe 订阅 + RevenueCat 移动内购 + 付费墙 + 配额限制 + 企业许可证。

## 4. 关键技术难点与对策

| 难点 | 对策 |
|---|---|
| CRDT 文档膨胀 | 定期快照 + GC，update 合并压缩；大文档分片 |
| 白板性能（元素多时卡顿） | 视口裁剪只渲染可见元素；后期上 WebGL/turbo-renderer；分层缓存 |
| 富文本与 CRDT 映射 | 用 Yjs 的 XmlFragment 或成熟的 y-prosemirror 绑定 |
| 多端存储一致性 | 统一存 Yjs update binary，存储层只做二进制读写，逻辑在引擎层 |
| 实时同步冲突 | CRDT 天然免冲突；服务端只做合并广播，不做业务合并 |
| Electron 包体积 | 只打包 web 产物 + 原生模块，按平台裁剪 |
| 移动端白板交互 | 简化工具集，手势优先，复杂编辑引导到桌面 |
| 鸿蒙无法复用移动 Web 壳 | ArkWeb 内嵌引擎快速见效，性能敏感层用 ArkTS 原生，对齐统一存储抽象接口 |

---

## 5. 建议开发节奏

- **先纵切再横切**：阶段一先做通"一种块从数据到 UI 到存储"的完整链路，再横向铺开更多块类型。
- **引擎与 UI 并行**：编辑器引擎和业务 UI 可由不同人并行，靠块注册表接口解耦。
- **平台适配尽早抽象**：阶段一就定义存储/文件接口，避免阶段三重构。
- **云是可选层**：本地优先意味着不接后端也能完整使用，云同步是增值功能。

### 桌面文件打开与拖放（2026-10-08）

主进程处理启动参数、macOS open-file、second-instance 与原生多文件选择器，复用单窗口并将请求放入有限队列。仅主窗口来源可通过 take / acknowledge IPC 领取文件字节；没有任意路径读取接口。每批 100 文件／50 MB、最多 8 批，文件大小在读取前检查并限制分配及读取长度。预览创建后确认消费；页面重载仍可领取未呈现批次，完全退出不持久化队列。安装包声明 md／markdown 文件关联，Windows 安装关联仍需实机验收。

应用级文件拖放优先识别 Markdown／ZIP 并进入现有导入预览；图片及其他附件复用正文媒体上传与白板图片存储。白板非图片附件先创建持久化附件文档，再生成现有 doc-card，不新增独立附件元素模型。原生打开在弹窗／忙碌时等待；拖放到背景被拦截，导入弹窗自身拖放保留原规则。导入／文件准备状态接入关闭前保存保护。


### 桌面文档深链实现

共享 `deep-link.ts` 定义 `mydoc://document` 查询参数协议，严格校验 workspace/doc、mode 和互斥 frame/block，拒绝路径、身份信息、端口、片段、未知／重复参数、控制字符和超长链接。主进程仅由 open-url、启动参数、second-instance 或本窗口导航接收链接，32 条有界去重队列。preload 仅提供 take/ack/notification，IPC 沿用主窗口主 frame 校验，不接受文件路径或任意执行操作。electron-builder protocols 注册 macOS URL Types 与 Windows 安装协议；开发不改默认协议归属。

渲染进程先确认目标工作区和非回收站文档存在，再 flush 当前工作区并导航；未找到目标不修改当前选择。native-intake 互斥管理深链和文件请求；弹窗和 busy 状态暂停，关闭弹窗后继续，ack 前重载可重新领取。文件预览呈现期间持有 intake，直到预览结束。正文块位置进入 WorkbenchTab.blockId 与 NavigationHistory，page/board/frame/block 模式与位置可恢复；代码块不存在由编辑器提示，画框沿用已有 frameRequest 错误反馈。跨工作区访问保留各自历史，不创建跨数据库内容同步。


### SQLite 自动备份与恢复

共享服务层 DatabaseBackups 由 Web Vite storage 服务和 Electron 服务启动／关闭，定时检查启用状态与 lastAutomaticAt。默认 24 小时、最近 7 份普通备份；独立 JSON 设置放在数据库旁，不随数据恢复回退。测试模式 Web 数据库不启用全库自动任务和管理接口，避免跨测试 scope 的快照／恢复。

VACUUM INTO 唯一 partial 文件生成包含 WAL 已提交内容的一致快照，完成后计算 SHA-256、统计文档／工作区／附件，原子改名并写清单；只有规范清单与现存文件进入列表和清理目标。普通备份按保留数清理，恢复前与更新前保护合计独立保留最近 3 份。失败记录错误并在下一分钟重试，配置存储失败保留原设置；切换目录只改配置、不移动旧备份。

预览和恢复均校验大小、哈希、schema user_version、SQLite quick_check、三张表结构、Yjs 更新与统计。恢复开始设置服务维护状态拒绝读写，校验成功后先生成保护快照，再 ATTACH 目标快照，以单一 IMMEDIATE 事务替换文档、附件与偏好；不覆盖数据库文件或绕开 WAL。事务错误回滚，保护备份失败不启动事务。同一恢复事务更新 SQLite 系统 scope 中的 generation，所有连接共享此代际；客户端请求携带初始化时的 generation；等待请求体后及获得写事务锁后重新检查维护／代际状态，阻止恢复前积压请求和其他旧页面覆写。渲染端先 flush 所有打开工作区和项目偏好，成功后重载，失败保留编辑页面。Electron 退出／重载守卫额外检查备份任务运行状态。

HTTP 管理接口仅接受有限间隔／数量、备份 ID 与操作；路径由服务持有，不能通过 HTTP 指定任意恢复路径。桌面 preload 提供经过主窗口验证的原生目录选择与打开入口。现有工作区 JSON 导出恢复与整库快照界面分开保留。

## 桌面发布完善

正式构建由 `scripts/desktop/release.mjs` 在对应平台预检证书、公证凭据，生成独立 builder 配置后构建；强制签名、macOS hardened runtime／公证、Windows SHA-256 与发布者名称校验。CI 仅手动触发并归档，不发布。普通开发配置继续生成未签名包。

electron-updater 在主进程运行，地址来自正式构建的 `app-update.yml`。默认无渠道、无网络请求，仅打包正式标记与 HTTPS 配置同时存在才开启；渲染器只通过受信 IPC 查询状态、切换自动检查、检查／下载／安装，不提供 feedURL 接口。关闭自动下载、普通退出安装、降级与预发布。

安装状态机先发保存握手并冻结编辑、等待所有打开文档／偏好提交，再创建完整 SQLite 更新前保护快照；之后才允许 updater 关闭窗口。失败恢复编辑和退出守卫，仅解除更新自身持有的数据库维护锁，避免打断其他恢复操作。UI 显示版本、渠道、进度、失败重试和安装前保护。签名、公证及真实两版更新仍依赖后续凭据／渠道验收；当前用户要求不配置发布渠道。详见 `docs/桌面发布.md`。

## 工作空间与服务端协作基础

按用户调整优先级：暂停移动端，先推进 AFFiNE 风格工作空间与 Web 同步。增加空间 flavour（本地／团队）、账户与成员服务及服务端同步 provider，SQLite 文件仍位于项目内。独立托管服务必须登录，个人存储按账户 scope，团队文档／附件按工作空间 scope。会话 token 仅哈希入库，Cookie HttpOnly／SameSite，密码使用 scrypt；请求校验账户绑定，旧标签页在账户切换后不能写入新账户。

共享 Yjs 更新经过服务端授权、二进制校验和写事务合并后由 SSE 广播；工作空间复用单个流，重连全量补发，远端 origin 防止循环提交。个人 uiPreferences 使用独立账户文档；Awareness 在线状态在内存中，服务端强制账户姓名／颜色并校验相对光标位置。移除成员关闭连接；永久删除文档以 tombstone 防止旧页面重新发布。

当前提供单进程可运行基础，后续推进权限失效编辑锁定、持久离线队列、增量握手、只读与文档权限、WebSocket／多实例、服务端备份及桌面同步。当前协议、部署与限制见 `docs/工作空间与协作.md`。


#### 协作可靠性补充（2026-10-08）

团队同步采用 SSE 广播加 HTTP state-vector 双向补齐；连接状态和持久化状态分别表达。查看者权限由服务端核对，在线撤销／降权后客户端暂停编辑并保留内存草稿，允许导出 Yjs 和 Markdown 内容。下一步的离线存储应继续使用项目／桌面 SQLite，不采用浏览器本地持久化。当前页面关闭保护及草稿下载不等同于持久离线队列。
