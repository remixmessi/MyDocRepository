# 工作空间与 Web 协作

参考 AFFiNE 的工作空间 flavour/provider、账户服务与同步网关划分：本地工作区继续沿用原存储，团队工作空间有服务端成员权限、独立文档 namespace 和共享附件。没有将 AFFiNE 的商业后端、原生 runtime 或整套 NestJS／GraphQL 直接搬入当前项目。

## 开发与独立服务

本地 `corepack yarn dev` 的工作区选项新增“团队工作空间”。支持账户注册／登录、创建空间、设置名称、邀请、成员管理、所有权转移及退出。登录与退出会重新载入，个人注册表与偏好按账户隔离。本地未登录的原数据库内容保留，退出后可再访问。开发服务默认仍仅监听 127.0.0.1。

独立 Web 服务：

```sh
corepack yarn server:build
corepack yarn server:start
```

默认访问 `http://127.0.0.1:8080`，必须先注册或登录。数据库为项目 `data/cloud.sqlite`，首次建立空表，后续启动复用，不携带用户数据；原 `data/mydoc.sqlite` 不迁移、不覆盖。服务端 SQLite 保存账户、会话、工作空间、成员、邀请、Yjs 文档与附件；个人文档／注册表／偏好使用账户 scope；请求绑定初始化账户，切换账户后的旧页面拒绝继续读写，团队文档使用空间 scope。

可配置 `MYDOC_HOST`、`MYDOC_PORT`、`MYDOC_CLOUD_DB_PATH`；邮件服务可配置 `MYDOC_SMTP_HOST`、`MYDOC_MAIL_FROM`、`MYDOC_SMTP_PORT`（默认 587，`MYDOC_SMTP_SECURE=1` 时默认 465）、`MYDOC_SMTP_SECURE`、`MYDOC_SMTP_USER`、`MYDOC_SMTP_PASS`，不配置时账户相关口令改为当场显示或写入服务端日志。提供给其他设备时需显式监听可达地址，正式环境在 HTTPS 反向代理后运行，并传递 `X-Forwarded-Proto: https`，让会话 Cookie 使用 Secure。不要把 Vite 开发服务直接当作公共团队服务：它保留已有未登录本地存储接口。

## 工作空间与权限

- 所有者：管理空间、成员、管理员、转移所有权、永久删除空间。
- 管理员：改名、邀请和移除普通成员，不能删除空间、移除所有者或修改其他管理员。
- 成员：读取、编辑共享文档与附件，可退出空间。
- 查看者：读取共享文档、附件及评论，可浏览白板、查找和导出正文；禁止写入或删除文档／附件、修改组织数据和管理空间。所有者可调整成员为查看者，邀请时也可选择查看者。
- 所有者必须先转移所有权才能退出；服务端事务保证转移后仍有一个所有者。
- 邀请使用随机一次性口令，数据库保存哈希，7 天有效，仅匹配注册邮箱可接受。当前没有邮件发送及邮箱验证，需由管理者自行把口令交给受邀人。
- 浏览器界面限制之外，每个 API 和同步连接均由服务端核对会话／成员权限。移除成员关闭连接，后续读取、写入、附件访问拒绝。

## 工作空间设置

“设置与成员”集中展示空间概览与管理操作：名称、创建时间、你的角色、所有者、按角色拆分的成员数量、文档数、有效邀请数，以及按文档和附件拆分的存储占用。概览、成员列表与邀请列表都由服务端按角色判定，查看者读取即被拒绝。

成员列表支持按姓名或邮箱搜索、按角色筛选、每页 20 条分页，筛选无结果时提示可清除条件。邀请列表显示受邀邮箱、角色、到期时间与过期标记，可撤销或对同一邮箱重新生成；重新生成会立即删除旧口令，旧口令不能继续使用，过期口令仍会列出但不能被接受。

角色调整、移除成员、退出空间、转移所有权和删除空间都需要二次确认，失败时显示服务端返回的原因。删除空间前列出将永久移除的文档数、附件数、存储量和受影响成员数，并要求输入工作空间名称；只有你一个成员时提示无法转移所有权，只能删除。成员与邀请每 8 秒刷新，操作完成后立即重载，避免按已失效的权限展示操作。

密码使用加盐 scrypt 保存；随机会话 token 的哈希保存于 SQLite，Cookie 为 HttpOnly、SameSite=Strict，期限 7 天。注册／登录、找回密码、邮箱验证与更改邮箱均有按 IP 与用途分别计数的请求频率限制；跨站 Origin 和 Fetch Metadata 拒绝。没有 OAuth 与 magic-link，这些继续列后续批次。

## 账户设置

“账户设置”可自助维护显示名称与头像、验证邮箱、修改密码、更改邮箱并管理登录设备。头像限制 256 KiB，只接受 PNG、JPEG、WebP，并按文件内容而不是声明的类型判断格式，上传失败不会影响已有头像。

修改密码要先输入当前密码，默认让其他设备重新登录，当前页面换发新凭据后继续可用。登录设备列表显示设备类型、IP、登录时间、最近活动与到期时间，可注销指定设备或除当前外的全部设备；被注销的设备立即失去访问权限，未提交内容只能在该设备上导出草稿。

邮件服务通过 `MYDOC_SMTP_HOST`、`MYDOC_MAIL_FROM`、`MYDOC_SMTP_PORT`、`MYDOC_SMTP_SECURE`、`MYDOC_SMTP_USER`、`MYDOC_SMTP_PASS` 配置，支持 STARTTLS 与 AUTH LOGIN。未配置时界面会明确说明原因：邮箱验证与更改邮箱的一次性口令直接显示给当前已登录的本人；找回密码的口令只写入服务端日志，需要联系运维获取，不会回传给请求方。

邮箱验证、找回密码与更改邮箱都使用一次性口令，数据库只保存哈希，1 小时内有效，重新发送会立即作废旧口令，使用过或过期的口令都不能再用。找回密码对已注册与未注册的邮箱返回完全相同的结果，不暴露账户是否存在；重置成功后该账户全部设备都需要重新登录。更改邮箱要先输入当前密码并验证新地址，确认后才生效；发往旧地址的未接受邀请会失效，需要邀请人按新邮箱重新邀请，界面在更改前后都会提示受影响的邀请数量。

登录过期与失去权限分开提示：会话到期时状态区说明页面内容与已暂存草稿仍保留，并给出重新登录入口，重新登录后继续提交此前排队的改动，不需要刷新页面。

## 同步与协作

HTTP 提交 Yjs 二进制更新，服务端验证后以 SQLite 写事务合并；提交成功才返回保存成功，并通过 SSE 实时广播给同空间的其他客户端。一个工作空间共用一个 SSE 连接，首次连接、重连及同一连接中新打开文档时，通过 `/sync` 交换 Yjs state-vector：服务端返回客户端缺少的更新和自己的向量，客户端应用后仅提交服务端缺少的改动。SSE 负责后续增量广播，不再在建立连接时下载整个空间。重复更新由 CRDT 幂等处理。使用 Yjs Awareness 与 ProseMirror cursor 插件显示协作光标，姓名与颜色来自服务端账户，在线状态仅在内存中、失联过期清理，不写入文档或数据库。

文档、标题、文件夹、组织数据与白板元素使用同一共享模型；附件保存在共享空间下，成员只能访问自己加入的空间。个人工作台／编辑器偏好使用独立的账户文档，不混入团队文档。永久删除文档保留服务端 tombstone，拒绝旧页面重新提交；回收站仍使用共享模型中的软删除。

状态区区分连接与差异补齐、已同步、断线待提交、写入失败及权限失效。断线可继续编辑，恢复联网或 SSE 重连后自动补齐双方变化，也可手动重试。成员移除、会话失效或账户改变时暂停正文、标题、白板和组织编辑；降为查看者后仍能阅读及导出。服务器在接收请求体后再次检查文档／附件写入权限，防止上传期间被撤销权限仍然提交。

服务可达时，每次更新先在当前账户 SQLite 中保存待提交条目和完整 Yjs 草稿，再发送协作更新；只有收到远端成功确认后才删除对应条目。提交失败记录原因、次数和下一次重试时间，采用 1 秒起步、最多 60 秒的指数退避，也可手动重试。重开文档时把当前代际的待提交更新与服务端数据合并；确认丢失可以重复发送，Yjs 合并保持幂等。登录过期、查看者降权、成员移除、账户切换和永久删除都会暂停发送，队列和草稿不转投其他账户或空间。状态显示已落盘待提交数量及最后确认时间，正在写入仍显示“正在保存”；未落盘时明确要求保留页面或导出草稿。状态区的草稿下载不含附件字节，不能作为完整备份。

侧栏工作区菜单和命令面板的“从草稿恢复”可导入工作空间／单文档草稿文件，也可在个人工作区点击“读取暂存草稿”读取当前账户 SQLite 的文档草稿。即使原空间已删除或访问权已撤销，也只能恢复为个人工作区的新文档，不复用原 ID、不重新授予权限；草稿不含附件字节。当前不支持合并回原文档。数据库恢复后，旧代际条目保留为草稿但禁止自动重放。服务完全不可达时，新改动仍只在页面内存，不能据已有待提交条目判断后续输入已经落盘。

离线能力边界按部署方式区分，不要一概视为“支持离线”：

- Vite 开发：存储插件与协作插件通常运行在同一 Vite 进程，分别使用项目 SQLite 与协作 SQLite。同步接口失败但存储接口可达时可暂存；Vite 进程退出或整个服务不可达时，没有独立本机写入通道。桌面本机 storage IPC 是另一种通道，但远程空间接入与完全断网编辑仍属于第 8 批。
- 独立托管 Web 服务：`/api/storage` 与 `/api/cloud` 由同一个协作服务进程和 `data/cloud.sqlite` 承载。该进程不可达时两条链路同时失效，普通浏览器没有其他持久写入通道。因此只有服务可达但同步链路失败时才能由服务端 SQLite 暂存；服务完全不可达时内容仅在页面内存，必须先导出草稿文件再关闭页面。
- 要让浏览器在完全断网后仍可关闭页面并恢复，需要桌面 SQLite 或本机代理进程，不通过浏览器 localStorage／IndexedDB 实现。

数据库结构版本为 2：在原有 documents／assets／preferences 之外，新增 `pending_updates`（待提交 Yjs 更新队列）与 `drafts`（草稿恢复条目）。两表按账户、服务器、工作空间、文档隔离，并记录写入时的数据库代际。启动按版本号分步迁移，已有数据库只补建缺少的结构，失败整体回滚且版本不前进。完整备份恢复只替换三张业务表，待提交队列与草稿保留不被覆盖；版本 1 的旧备份仍可预览和恢复。当前同步为单进程 SSE + HTTP，不是 WebSocket／Redis 多实例网关。反向代理需禁用 SSE 缓冲并允许长连接。同一协作数据库只运行一个协作服务实例；Vite 与独立 Web 服务不可同时操作同一团队数据库，否则实时广播不会跨进程传递。

这些不标记为 AFFiNE 完整等价实现。当前是可以实际运行的账户、工作空间与协作基础。
