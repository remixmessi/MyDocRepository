# MyDocAgent 实现执行清单

创建日期：2026-10-28。依据：[MyDocAgent 实现设计方案](./MyDocAgent实现设计方案.md)。状态：A0 本地技术验收完成；A1 持久化基础已实施，整批未验收。

## 执行与记录规则

- 按 A0 → A1 → A2 → A3 → A4 顺序执行；A5 为按需扩展，不阻塞首版。批内按编号推进，先完成依赖再接入消费方。
- `[ ]` 未完成或未通过验收，`[~]` 进行中，`[x]` 已实现且有验证证据。实现完成但实机/供应商验证未做时，保留对应验收项未勾选，不把整批标为完成。
- 每批记录实现范围、提交/差异、验证命令与结果、截图/报告路径、未验证事项和下一步。测试数据使用独立临时库、资料目录与账户，不修改个人业务库。
- 常规、已明确授权的可恢复操作连续执行；需要确认时先生成具体变更和影响范围，不对每个工具重复询问。
- 领域规则保持单一实现：HTTP、IPC 和 Agent 共用授权、命令与持久化服务；界面不执行模型循环，worker 不直接访问 SQLite 或获得密钥。
- 数据库一律通过 `SQLiteProjectDatabase` 启动检查；协作宿主在同一启动写事务执行 `upgradeCloudDatabase`。新增结构必须带增量迁移、列检查及版本推进，失败回滚并关闭数据库停止启动。禁止改写已发布迁移或请求时建表。
- 方案记录的公共 4／协作 13 仅为调研基线。每次结构改动先检查当前代码，使用实际下一版本，不预占版本号；遵守 [数据库迁移约定](./数据库迁移.md)。
